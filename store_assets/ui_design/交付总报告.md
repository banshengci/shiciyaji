## 四、数据模型（Poem Schema）

原型诗词数据位于 `index.html` 内 `const poems=[...]`（当前 8 首示例）。工程端应替换为此结构的数据源（接口 / 本地 JSON / DB）：

```ts
interface Poem {
  id: number;
  title: string;        // 诗名
  dynasty: string;      // 朝代：唐/宋/元/明/清…
  author: string;       // 作者
  genre: string;        // 体裁标签：唐诗/宋词…
  first: string;        // 首句预览（列表/卡片用）
  content: string;      // 正文（\n 分句）
  note?: string;        // 注释
  translation?: string; // 译文
  appreciation?: string;// 赏析
  background?: string;  // 创作背景
  fav?: boolean;        // 是否收藏
  learned?: boolean;    // 是否已学习
}
```

> 需求目标为 **70 首**诗词，原型仅 8 首占位，需由 Trae 接入真实数据并扩充到 70 首。

## 七、已知限制 / 与需求的差距

1. **数据量**：原型仅 8 首示例，需求目标 70 首，需真实数据接入。
2. **手势交互**：需求 5.1 的「左滑返回/下拉刷新/长按快捷操作」原型未实现（仅点击导航），需在工程端补齐。
3. **可选动画**：需求 5.2「水墨 loading / 撒花盖章」为可选，原型未做。
4. **空状态插画**：需求 P2「空状态插图」原型用简易图标占位，可补插画。
5. **字体依赖**：原型依赖在线 Web 字体，工程端须本地打包 Noto Serif SC。
6. **真实功能**：收藏夹增删改、登录、学习计划、朗读(TTS)、分享等均为 UI 占位，无后端。
