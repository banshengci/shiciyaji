# 诗词雅集 · 下一阶段功能规划

> 盘点基准：2026-09-16 工作副本（`lib/` 39 个 Dart 文件、DB v8、1320 首诗词、334 条测试全绿）
> 本文只回答「做什么、为什么、先做哪个、怎么做完算数」，不含排期。

## 一、盘点结论（为什么是这些功能）

### 1.1 已有能力

首页（今日推荐 / 今日诗单 / 复习卡 / 四个快捷入口）、诗库（朝代 · 体裁 · 主题筛选，列表 / 网格）、
全文检索（含拼音全拼与首字母）、收藏与收藏夹、学习计划（预置三套 + 自建 + 追加 + 总进度）、
学习打卡与艾宾浩斯复习、阅读历史、笔记、离线诗词包（唐诗 600 / 宋词 500 / 小学 150）、
TTS 朗读（整篇）、背诵自测（自评通过 / 未过）、飞花令、诗词卡片分享（PNG）、
作者浏览与作者详情、统计图表、成就、备份恢复、明暗主题、全局字号。

**结论：功能广度已经够。** 缺口不在「再加一类东西」，而在三处**深度**：
内容可信度、学习闭环的最后一公里、以及"打开 App 的理由"。

### 1.2 数据体检（本次新发现，也是最重要的一条）

对四个数据源逐条检测「译文 = 原文复制 / 赏析命中模板句 / 赏析过短 / 背景为
`作者+诗名` 拼接」：

| 数据源 | 篇数 | 赏析为占位 | 背景为占位 | 译文非真译文 |
| --- | --- | --- | --- | --- |
| 预置 `poems.json` | 70 | 0 (0%) | 0 (0%) | 0 (0%) |
| `packs/tangshi.json` | 600 | 558 (93.0%) | 546 (91.0%) | 289 (48.2%) |
| `packs/songci.json` | 500 | 451 (90.2%) | 450 (90.0%) | 310 (62.0%) |
| `packs/xiaoxue.json` | 150 | 96 (64.0%) | 85 (56.7%) | 50 (33.3%) |
| **合计** | **1320** | — | — | **1105 首 (83.7%) 至少一项为占位文本** |

典型样本（宋词《夜游宫·贺铸》）：

- 赏析：`此词以「夜游宫」为题，章法铺叙有序，上下片衔接自然，语言清丽，意境完整，善用风、江等意象…`
- 背景：`《夜游宫》为贺铸的作品。全篇围绕题意展开…`
- 译文：`江面波纹皱縠。`（就是原文首句）

来源已确认：`tools/auto_fill_content.py` 的文件头写明「为仍缺译文的诗词生成完整但偏说明性的 T/A/B」，
**作者是有意保守生成的**（不编造史实）。问题不在生成，而在**界面把它当成"赏析"原样展示** ——
用户翻到第 300 首时，读到的是流水线套话，这是在消耗信任。

### 1.3 学习闭环的断点

- **计划只有总进度，没有"今天学哪几首"。** `study_plans` 只有 `poem_ids` 一个 JSON 串，
  自建页的输入框提示写着「如：每日精读五首」，但代码里**没有任何"每日"机制**。
  用户建了 300 首的计划，第二天打开不知道从哪开始。
- **「背诵自测」是自评**：`recall_quiz_page.dart` 只做「显示原文 / 隐藏原文 + 通过 or 未过」，
  数据来自用户自觉，无法证伪，也无法驱动复习调度。
- **朗读是一整篇**：`tts_service.dart` 只有 `speak(整段文本)`，没有断句、没有进度回调、
  不能单句重听 —— 而这恰恰是"跟着读"最需要的。

### 1.4 技术约束（决定方案形态）

- **离线优先**：`pubspec.yaml` 里**没有任何 http 客户端**。任何需要联网的功能都要新依赖 + 违背定位。
- **无状态管理库**：`StatefulWidget + setState` 局部刷新。1320 首规模下够用，不构成问题。
- **分享物走 PNG**：`RepaintBoundary.toImage` → 分享，且刻意钉死配色与字号（`FixedScaleCanvas`）。新分享物复用它。
- **DB 版本 8**，新增字段/表要走迁移 + 迁移测试（仓库已有 `test/v7_migration_test.dart` 惯例）。
- **仓库冗余**：`assets/data/pack_{tangshi,songci,xiaoxue}.json` 与 `poems_v2.json` 是扩充前的旧中间产物
  （合计约 0.8MB），只被 `tools/` 脚本引用、未列入 `pubspec.yaml` 的 assets（不进包），属可清理项。
- **README 与代码不符**：README 写「雅集视觉风格（松绿 / 宣纸 / 松烟墨）」，实际令牌是
  黛蓝 / 朱砂 / 宣纸白（`lib/core/design_tokens.dart`）。一行修正。

## 二、目标用户

| 分层 | 是谁 | 判据 | 核心任务（想做成的样子） |
| --- | --- | --- | --- |
| **主用户** | 作者本人 | README 明确「个人使用为主」 | 每天花 10 分钟读两首、听到能读顺、知道这个月没白过 |
| **次用户 A** | 家长 / 带孩子背诗的家长 | 内置「小学必背」离线包、计划预置 | 陪着孩子读准、知道今天该背哪首、能检查是不是真背下来了 |
| **次用户 B** | 学生 / 备考者 | 艾宾浩斯复习 + 背诵自测 + 统计 | 有计划地过完一册、能被客观检验、知道哪里还不会 |
| **次用户 C** | 泛诗词爱好者 | 赏析 / 背景 / 作者页 / 分享卡片 | 读到可信的解析、能顺手查一个字、能把喜欢的一首分享出去 |
| 边缘 | Releases 尝鲜者（GitHub 公开仓） | 三端 CI 出包 | 装上就能用，不联网 |

**共同点：三类用户全部集中在「想读懂 + 想坚持 + 想验证」这三件事上**，本规划的 8 项功能即按此收敛。

## 三、功能清单

### P0-1 · 赏析可信度分级与本地补写

| 项 | 内容 |
| --- | --- |
| **要解决的问题** | 1320 首里 83.7% 的译文/赏析/背景是脚本生成的说明性占位文本，界面不加区分地称作「赏析」（证据见 §1.2）。同时：离线包升级会覆盖用户内容，用户现在**没有任何地方**可以写下自己的理解并长期留存。 |
| **目标用户** | 次用户 A / B / C（所有点开赏析的人） |
| **核心作用** | ① 给每条译/析/景打质量等级（精校 / 说明性补充 / 无），界面如实标注而不是假装；② 开放「我来补一段」的本地覆盖，写下的内容跟离线包升级解耦、并被备份带走。 |
| **主要场景** | 点开一首冷门诗 → 看到徽标「本赏析为说明性补充，非专家精校」→ 不误导；自己查了资料 → 补写一段 → 下次升级离线包仍在；补写过的诗在诗库里有"已补全"角标。 |
| **优先级** | **P0** —— 它决定后面所有内容型功能的可信度基准。先诚实，再谈美。 |
| **关键步骤** | 1. 写 `tools/audit_content_quality.py`：把上面那份检测器固化（译文是否原文复制 / 模板句特征 / 长度 / 背景拼接），输出 `assets/data/content_quality.json`（`poem_id → level`），同一份判据后续在 Dart 侧也用，避免两套算法；2. DB v9 迁移：`poems` 加 `content_level` 列 + 新表 `poem_content_overrides(poem_id, field, content, updated_at)`；3. `poem_detail_page.dart`：赏析区顶部徽标 + 「补充赏析 / 译文」入口（走 `note_dialogs.dart` 已有的弹窗范式）；4. 读取顺序统一为 `overrides → pack → 预置`，抽成 DAO 单一入口；5. 覆盖内容纳入 `createBackup` / `restoreFromBackup`（`database_helper.dart:2064` 起的备份区）；6. 统计页/诗库加「内容补全进度」一栏。 |
| **预期产出** | 质量清单 JSON（1320 条）+ 检测脚本 + DB v9 迁移 + 详情页徽标与补写入口 + 备份格式兼容 + `test/content_quality_test.dart`（全量逐首对账、覆盖优先级、备份往返）+ `test/v8_migration_test.dart` |
| **验收** | 全量 1320 首：分级结果与 JSON 一致；覆盖后读到的内容与写入一致且升级离线包后不丢；旧版本备份文件能导入新版本。 |

### P0-2 · 逐句跟读（朗读断句 + 当前句高亮）

| 项 | 内容 |
| --- | --- |
| **要解决的问题** | 朗读是「一整段念到底」：没有进度、不能重听某一句、断不开句读（证据见 §1.3 第三条）。学诗的关键动作是**跟着读**，现在做不到。 |
| **目标用户** | 主用户（通勤听）、次用户 A（带孩子逐句读）、次用户 B（记读音） |
| **核心作用** | 把正文按句读切开逐句朗读：当前句高亮、点任意句从此处开始、单句循环、句间停顿可调。 |
| **主要场景** | 地铁上听一首长词，没听清「醉里挑灯看剑」→ 点那一句重听；陪孩子读《静夜思》→ 单句循环三遍再下一句；沉浸模式下大字 + 高亮跟读，屏幕不需要点。 |
| **优先级** | **P0** —— 现有能力的"最后一公里"，改动集中在两个文件，收益立刻可见。 |
| **关键步骤** | 1. `utils/verse_splitter.dart` 纯函数：按 `，。？！；、` 断句，保留标点与换行结构，处理词的长短句与「·」；2. `tts_service.dart` 增 `speakSequence(List<String>, onSentence(int))` / `loopAt` / `stop`，串行 await + completion 回调驱动下一步（**不依赖** `setProgressHandler` —— Windows 桌面端支持不全）；3. `poem_detail_page.dart` 跟读条（高亮 + 点句定位 + 单句循环 + 语速沿用现有档位）与沉浸模式复用；4. 音频焦点与页面退出时的停止清理。 |
| **预期产出** | 断句工具 + TTS 序列朗读能力 + 详情页/沉浸模式跟读 UI + `test/verse_splitter_test.dart`（1320 首全量：无空句、标点守恒、句数分布合理）+ 渲染测试 |
| **验收** | 全量 1320 首断句零空句、拼接回原文与原文等长；朗读中退出页面无残留播放；桌面端与移动端行为一致。 |

### P0-3 · 客观题型自测（填空 / 下句 / 作者朝代）

| 项 | 内容 |
| --- | --- |
| **要解决的问题** | 「背诵自测」是自评，学得怎么样全凭自觉（证据见 §1.3 第二条）；复习调度也因此缺一个可用的客观信号。 |
| **目标用户** | 次用户 B（学生/备考）、次用户 A（验收孩子）、主用户（自检） |
| **核心作用** | 由本地数据自动出题，答对答错写回学习记录，成为复习调度的第二个信号源（与"自评为过"并列）。 |
| **主要场景** | 睡前 10 题：给出「举头望明月」选下句；挖空「疑是地上__」；给出诗句选作者/朝代。错题自动进复习队列。 |
| **优先级** | **P0** —— 把「我学过了」变成「我确实答对了」，是学习类应用的核心价值兑现。 |
| **关键步骤** | 1. `core/quiz_generator.dart` 纯函数：三种题型生成器，干扰项从同朝代/同体裁/同字数池里取且**排除正确答案与重复项**；2. 题型壳复用 `recall_quiz_page.dart` 的导航骨架，新增 `quiz_page.dart`（或加"客观题模式"开关）；3. 结果写 `study_records`（沿用既有 status 取值规范，避免与艾宾浩斯冲突）；4. 错题在复习页与统计页可见（错题率、易错诗排行）；5. 从学习计划详情页可直接发起该计划范围的测验。 |
| **预期产出** | 出题器 + 答题页 + 学习记录联动 + 统计入口 + `test/quiz_generator_test.dart`（全量数据：每题唯一正确答案、干扰项互不重复且不等于答案、选项数恒定、短诗不出超出内容的题） |
| **验收** | 全量 1320 首生成三种题型零异常、零重复选项；答错后错题出现在复习流；同一首诗的题不会把答案写进题目。 |

### P1-4 · 计划排期：把计划变成"今天的几首"

| 项 | 内容 |
| --- | --- |
| **要解决的问题** | 计划只有总量与进度，没有每日分配（证据见 §1.3 第一条）。300 首的计划看不到"今天从哪首开始"。 |
| **目标用户** | 次用户 A / B、主用户 |
| **核心作用** | 计划加「每日定量 + 起始日期」，首页与计划页直接给出今日篇目（自动跳过已学），与艾宾浩斯复习合并为一张「今日任务」卡。 |
| **主要场景** | 建计划时填「每天 3 首」→ 之后每天打开首页就是「今日 3 首」，做完打勾；断卡三天回来不会堆成 12 首压垮人（按序推进而非补作业）。 |
| **优先级** | P1 —— 价值高但依赖 P0-3 的复习信号才能做得干净；且要动 DB 迁移，和 P0-1 合并成同一次 v9 迁移更省事。 |
| **关键步骤** | 1. `study_plans` 加 `daily_target` / `start_date`（与 P0-1 同一次 v9 迁移）；2. `core/plan_scheduler.dart` 纯函数 `todayPoems(plan, studiedIds, date, scope)` —— 边界：篇目耗尽、超额完成、断卡、同日改定量；3. 首页新增「今日任务」卡（替换现有纯复习卡的位置，复习作为其中一项）；4. `study_plans_page.dart` / `create_plan_page.dart` 定量与进度展示；5. 旧计划无定量时按"不限量"兼容显示。 |
| **预期产出** | 迁移 + 排期纯函数 + 首页今日任务卡 + 计划页改造 + `test/plan_scheduler_test.dart`（含所有边界）+ 旧数据兼容测试 |
| **验收** | 老用户升级后原计划照常显示、进度不丢；断卡后不出现"欠账"列表；今日任务与复习不重复计数。 |

| **预期产出** | 聚合器 + 月报卡 + 导出管线去重 + `test/report_builder_test.dart`（空月 / 月末 / 闰年 / 单日集中学习） |
| **验收** | 空月份不崩且有友好空态；同一个月多次导出结果像素一致（钉死字号配色的意义所在）。 |

### P1-6 · 每日提醒（本地通知）

| 项 | 内容 |
| --- | --- |
| **要解决的问题** | 打卡容易断，全靠用户自己想起来打开 App。 |
| **目标用户** | 主用户、次用户 A / B |
| **核心作用** | 可设时间点的本地通知，文案带当天篇目名，点击直达该诗。 |

| **验收** | 关闭开关后不再有通知；改时间后旧调度被取消；权限被拒时有明确提示而非静默失败。 |

### P2-7 · 点字查字：逐字拼音与该字在别处的用例

| 项 | 内容 |
| --- | --- |
| **要解决的问题** | 遇到不认识的字只能整首搜，没有"就地查一下"的路径；`poems.notes`（逐词注释）字段全库为空（覆盖率 0）。 |
| **目标用户** | 次用户 A（教孩子认字）、次用户 B |
| **核心作用** | 点正文任意一字 → 弹出「拼音 + 该字出现在哪些诗句里」的小卡（点结果可跳转）。**不做释义** —— 现在没有可离线分发的词典数据，编不出来就不假装有。 |
| **主要场景** | 读《蒹葭》卡在「溯洄」→ 点字看拼音与其它用例，顺带发现同字名句。 |
| **优先级** | P2 —— 有价值的阅读辅助，但不解决核心闭环；且要做完整（含释义）需引入词典数据集，体积与许可都要评估。 |

## 四、优先级与理由

**排序原则：先诚实，再让人学得下去，最后才是好玩。**

1. **P0 三项全部指向"这个 App 说的话可不可信、动作有没有用"**：
   P0-1 解决"赏析是不是真的"，P0-2 解决"能不能跟着读"，P0-3 解决"学没学会有没有凭据"。
   这三项做完，产品在「读懂 / 坚持 / 验证」上的地基才算平。
2. **P1 三项是"让人更想回来"**（排期、月报、提醒）：价值真实，但都建立在 P0 的地基上 ——
   没有客观题与排期，"今日任务"只是一个待办列表。
3. **P2 两项是趣味与延伸**，且 P2-7 与 P2-8 应共用同一份"含某字/某词的诗句"索引，届时一起做更省。

依赖关系：**P0-1 与 P1-4 共用同一次 DB v9 迁移**（建议一起做迁移部分，功能可分两批）；
**P2-7 与 P2-8 共用诗句子串索引**；P1-5 与 P0-2 都要求"导出物/展示物钉死尺度"，沿用既有约定。

## 五、明确不做（以及为什么）

| 不做 | 理由 |
| --- | --- |
| 云端同步 / 账号体系 | 定位是离线优先（`pubspec` 无任何 http 客户端），个人使用场景下多端同步的收益 < 帐号、隐私、冲突合并的长期成本。现有"备份文件 + 分享转存"已覆盖换机。 |
| 在线诗词库 / 联网抓取 | 同上；离线包机制已覆盖扩充诉求，且联网抓取的许可与稳定性都是长期负担。 |
| AI 生成赏析补全长尾 | **方向相反**。问题恰恰是"看起来像赏析的套话"太多；先做分级与人工/本地补写，才谈得上生成。生成要留到有可信基线之后，且必须标注来源。 |
| 诗词地图（地名/行迹） | 地图数据在中国境内有严格合规要求（中国地图必须使用合规审图号数据），个人项目不值得承担。 |
| 引入状态管理框架 / 大规模重构 | 1320 首、单机、局部刷新的规模下，`setState` 不构成瓶颈。为重构而重构会打断连续交付。 |
| 逐词注释（`poems.notes`）全量补齐 | 1320 首的逐词注释工作量远超维护能力，且无可靠离线数据源。改为 P2-7 的"点字查拼音 + 用例"这一可交付子集。 |
