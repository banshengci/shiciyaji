## 数据备份 / 恢复功能（本轮新增）

### 动机
全部用户数据（收藏 / 收藏夹 / 学习计划 / 打卡 / 笔记 / 阅读历史 / 离线包）只存在本地 SQLite，
重装或换机即丢失。个人使用场景下，备份/恢复是最高价值功能。

### 数据层（lib/data/database/database_helper.dart）
- 新增 `exportAllData()`：仅导出用户表，剥离自增 id（favorites/notes 等），避免恢复冲突。
- 新增 `importAllData(Map)`：事务内「合并导入」——collections/studyPlans 先查后插去重；
  favorites/notes/readingHistory 按自然键 EXISTS 去重；study_records 用唯一索引去重；
  installedPacks 存在则跳过。返回各表「实际新增行数」摘要。
- 新增 `getBackupDirectory()`：应用支持目录下的 `backups/`（无需存储权限）。
- **关键坑**：`insert(... ignore)` 在 sqlite 冲突时 `last_insert_rowid()` 返回的是「上一条语句的旧 rowid」，
  不是 -1，故不能用 `id != -1` 判断「是否新增」。必须显式 EXISTS 查询再插。已据此修正。

### 测试（test/backup_test.dart，3 个，全绿）
- 覆盖导出完整性 / 同库重复导入幂等（0 新增）/ 全新库完整恢复 + 再导出一致。
- 注意种子数据：`addFavorite(2)` 不指定收藏夹会自动建「默认收藏」，故 collections=2。

### UI（lib/presentation/pages/settings_page.dart）

- 新增依赖 `file_selector ^1.0.3`、`share_plus ^7.2.2`（pubspec + pub get 已锁）。

## 自动备份（本轮补充，完成备份/恢复闭环）

### 动机
手动备份仍可能忘记，对个人使用仍有丢失风险。补全「每次启动自动备份」以防万一。

### 实现
- `DatabaseHelper.createAutoBackup({keep=5})`：导出全部用户数据 → 写 `backups/auto_backup_<时间戳>.json`
  → 列出该目录 `auto_backup_*.json` 按文件名（含时间，字典序即时间序）排序 → 仅保留最近 keep 份，
  删最旧的超量文件。
- `DatabaseHelper.getAutoBackupCount()`：统计已存自动备份份数（异常时返回 0）。
- `preInit()` 在 `ensurePresetPlans()` 之后、try 内调用自动备份：读取 `shared_preferences` 的
  `auto_backup`（默认 true），开启则 `createAutoBackup()`，失败仅告警不阻塞启动。
- 设置页新增「自动备份」SwitchListTile：开关绑定 `auto_backup`；开启时立即生成一份并 toast 路径；
  副标题显示「已存 N 份」（`getAutoBackupCount`）。
- test/backup_test.dart 新增第 4 个用例：连续生成 4 份(keep=2) → 校验文件存在且为合法备份 JSON、
  `getAutoBackupCount() <= 2`。因 `getApplicationSupportDirectory` 在 flutter test 无平台实现，
  setUpAll 用 `setMockMethodCallHandler` 把 `plugins.flutter.io/path_provider` 的
  `getApplicationSupportDirectory` 指向 `Directory.systemTemp` 临时目录（需 import flutter/services）。
