### 技术要点与踩坑

1. 图标/插画一律用 `type:"frame"` + `svg` 属性插入（自动解析为 FrameNode 矢量子节点），**不要**用 emoji 或文本节点拼。
2. 复制标签栏（`C(...)`）时若想用 `descendants` 改选中态，路径必须是 `<copyId>;<originalDescendantId>`，且原节点 ID 必须真实存在 —— 否则报 `Copy descendant not found`。本次改用「删除残留 + 手动重建」更稳。
3. 用 `M(nodeId, parentId)` 修正标签栏父级错位（曾被插到状态栏之前）。
4. 详情页溢出：收紧 `gap`、`paddingTop/Bottom`，长文本列宽改 `fill_container`。
5. 设 `layout:"horizontal"` 前若节点是 layout NONE，需先 `U(id,{layout:"horizontal"})` 才能让对齐属性生效。
6. 本会话模型**不支持读取图片**，`capture_screenshot` 无法用于视觉校验 → 改用 `export_nodes` 导出 PNG/PDF 作为交付与核查手段；`capture_layout(problemsOnly:true)` 用于检测溢出/裁切。

### 关键实现要点

1. **图标着色不走 `currentColor`**：flutter_svg 不支持 CSS 变量，改用
   `SvgPicture.asset(..., colorFilter: ColorFilter.mode(color, BlendMode.srcIn))`。
   好处是 32 份 SVG 保持原样，天生跟随明暗主题，不用为每套主题各导一份资源。
2. **SVG 必须补 `viewBox`**：Ardot 导出的 SVG 只有 `width/height` 没有 `viewBox`，
   flutter_svg 缩放会失效。用 `tools/fix_svg_viewbox.py` 批量补成 `viewBox="0 0 26 26"`。
3. **`PoemIcon.icon` 是 `Object`**（`String` = 自有图标，`IconData` = Material 兜底），
   所以迁移期可以混用、不会编译失败；没有语义对应项的图标（箭头/加号/删除/刷新/
   展开收起/锁/云/文件夹…）一律保留 Material。
4. **`IconData` 重写了 `==`，不能做常量 Map 的键** —— `kMaterialToPoemIcon` 必须是

### Android 签名的处理（关键）

**keystore 与密码绝不能入库**（已在 .gitignore）。CI 通过 3 个 GitHub Secrets 注入：

| Secret 名 | 内容 |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `android/app/shici-release.jks` 的 base64（3656 字符） |
| `ANDROID_STORE_PASSWORD` | `key.properties` 的 storePassword |
| `ANDROID_KEY_PASSWORD` | `key.properties` 的 keyPassword |

工作流逻辑：`if [ -n "$KS_B64" ]` → 还原 jks 与 key.properties，用 release 签名；
否则 `::warning::` + 回退 `flutter build apk --debug`（仍能安装，**但与 release 签名不同源，
会导致覆盖安装失败**，正式发版前必须配齐 Secrets）。

配置清单已生成为**本机文件 `dist/ci-secrets.txt`**（含 base64 与密码，`dist/` 已 gitignore）。
**注意：不要把密码打印到对话里**，写文件让用户自行复制。

### 推送经验（代理 502 的随机性）

同一批推送，失败分布完全随机：`main` 连续 **12 次**失败 → `tag` 第 **4 次**成功 →
再试 `main` 第 **1 次**就成功。**结论：不要因为几次失败就断定推不上去，循环重试
（间隔 3–4 秒、上限 12–20 次）几乎总能成功。**

另外：**推送 tag 会连带上传它指向的 commit 及其祖先**，所以 tag 推成功后，
即使 `refs/heads/main` 还没更新，代码对象也已在远端，CI 照样能跑。
