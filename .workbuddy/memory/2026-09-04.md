## 继续完善 shici_yaji：新增「背诵自测」（主动回忆训练）

### 背景与定位
复习页（ReviewPage）是**艾宾浩斯按周期回顾**（被动、按 1/2/4/7/15/30 天推送）；
本次新增的「背诵自测」是**主动检验是否真的背下来**（隐藏原文 → 自背 → 对照 → 记结果），
两者互补，不重复、不冲突。

### 数据层（lib/data/database/database_helper.dart）
- 新增 `getPoemsByIds(List<int> ids)`：按 id 批量取诗，**保持传入顺序**，
  自动跳过不存在/已删除的 id；内部分批（每批 500，规避 SQLite 999 变量上限），
  避免逐条 `getPoemById` 的 N 次查询。
- 新增 `recordRecall(poemId, {required bool remembered})`：
  remembered=true → status「自测通过」；false → 「自测未过」。
  用 `ConflictAlgorithm.ignore` 依托 study_records 唯一索引 `(poem_id, study_date, status)`
  做同日同结果去重；同日「通过」与「未过」可并存（status 不同）。

### 新页面（lib/presentation/pages/recall_quiz_page.dart）
- `RecallQuizPage(title, poemIds, randomLimit=20)`：
  - 传 `poemIds` → 按该列表自测（用于学习计划）；
  - 不传 → 随机抽 20 首（复习页入口）。
- 交互：隐藏原文占位 → 「显示原文」对照 → 「记住了 / 没记住」→ 记录并前进；
  结束时展示「记住 / 未过 / 正确率」汇总，可「再来一轮」。
- 视觉沿用 AppTheme（songLv 松绿 / zhuShaHong 朱砂红 / daiLan 黛蓝）+ serif 正文。

### 入口
- 复习页统计卡底部新增常驻按钮「背诵自测（随机 20 首）」→ 随机模式。
- 学习计划详情页 AppBar 新增「背诵自测」动作 → 按该计划的 poemIds 自测。
- 顺带把学习计划详情页的 `_loadPoems` 从逐条 `getPoemById` 循环改为批量 `getPoemsByIds`

## 继续完善：新增「拼音搜索」（全拼 + 首字母）

### 动机
背诗常见场景是「记得音、写不出字」（如只记得 chuang qian ming yue guang）。
原搜索只有中文 LIKE 路径，拼音输入一律零结果。

### 设计取舍（重要）
- `poems` 表**没有** pinyin 列，且不愿为此加列 + 写迁移（迁移成本高、离线包也要改）。
- 结论：**中文关键词完全走原 SQL 路径不动**（零性能回归），
  仅当关键词是纯 ASCII 字母（`^[a-zA-Z]+$`）时走**内存拼音索引**。
- 索引结构：每首诗一条 `(id, full, initials)`，
  full=全拼串（chuangqianmingyueguang），initials=首字母串（cqmyg）；
  标题+正文拼接后转拼音，**跳过标点/换行**（py 为空串的字符不写入），
  因此 `mingyueguang` 能跨「，」「\n」命中。
- 匹配：`full.contains(kw) || initials.contains(kw)`，大小写不敏感；
  命中后复用 `getPoemsByIds` 取详情，再叠加 dynastyId/type 过滤。

### 缓存一致性（踩坑点）
索引是 static 缓存，**所有增删诗词的路径都必须调 `invalidatePinyinIndex()`**：
`_loadInitialData` 后、`importPack` 后、`uninstallPack` 后，
以及测试用的 `setDatabaseForTesting` / `resetForTesting`（否则内存库之间串数据、用例互相污染）。

### 性能与 UI 流畅性（关键改进）
- 实测 2000 首（装满离线包规模）首次构建 **~870ms**（桌面），手机上估计 2-3s
  → 若在主 isolate 一次性跑完会**卡住 UI**。
- 解决：构建循环**每 200 首 `await Future.delayed(Duration.zero)` 让出事件循环**，
  把一次长阻塞切成多个小片；`main()` 里 `runApp` 之后调 `warmPinyinIndex()`
  **后台预热**（fire-and-forget），用户敲拼音时基本已就绪。
- 并发去重：`_pinyinBuilding` 保存进行中的 Future，多次并发搜索复用同一次构建。
- 脏读防护：`_pinyinGeneration` 代次计数，`invalidatePinyinIndex` 自增；
  构建完成时代次不一致 → **丢弃结果**。
  ⚠️ 由此产生的坑：丢弃后 `_pinyinIndex` 仍为 null，原来 `searchPoems` 里写
  `for (final e in _pinyinIndex!)` 会 **null 崩溃**。
  改成 `_ensurePinyinIndex()` **返回 List**（内部最多重试 3 次，兜底返回 const []），
  调用方永远拿到非空列表。

### UI 提示（lib/presentation/pages/search_page.dart）
- 输入框 hint 改为「搜诗词、作者，或拼音 cqmyg」；空结果文案带拼音示例。
- 建议页底部加一条灰底提示卡：说明全拼/首字母两种用法（否则用户不知道有这功能）。

### 测试（新增 19 个，全绿）
- `test/pinyin_search_test.dart`（18）：PinyinHelper 基础、全拼、首字母、
  大小写不敏感、跨标点、朝代/体裁叠加、无匹配、中文仍走 SQL、空关键词、
  缓存失效重建、**并发一致性**、**构建中被失效不崩溃**、预热后命中。
- `test/pinyin_perf_test.dart`（1）：2000 首首次构建 <3s、缓存命中 <100ms。

## 继续完善：新增「飞花令」游戏

### 动机
诗词学习类 App 的高价值差异化功能。飞花令是经典古诗词游戏，
以某个汉字为「令」，选出/背诵包含该字的诗句。
既检验积累量又有游戏乐趣，远比被动浏览更能驱动主动记忆。

### 数据层（database_helper.dart）
- `getPoemsContainingChar(char, {dynastyId})`：
  `WHERE p.title LIKE ? OR p.content LIKE ?`（title+content 都搜），
  随机乱序返回 `ORDER BY RANDOM()`，供飞花令出题用。
- `getRandomPlayChar({minCount: 3})`：
  扫描前 2000 首诗的 content，统计每个汉字出现在几首不同诗中，
  排除 minCount 以下（太少不好猜）和 >60%（太常见无趣，如「的」「了」）的字，
  按频次加权随机抽一个。

### 游戏页（lib/presentation/pages/flying_flower_page.dart）
- **开始页**：飞花令文化简介 + 今日令字展示（朱砂大字）+ 含该字的诗数 + 开始按钮。
- **游戏中**：四选一（哪首诗包含该字），顶栏实时显示进度/分数/连击，
  每 5 题触发倒计时条（60s，超时自动判错）。
  连击加分：基础 10 + 连击奖励（最高 +15），错误扣 5 分（不低于 0）。
  答错/超时后 2s 自动跳下一题，用绿色/红色高亮显示正确/错误选项，
  底部提示栏显示「xxx出自《xxx》」。
- **结算页**：总分（大号朱砂数字）+ 正确/错误/正确率三项统计 + 评价语
  （≥200 诗神 / ≥100 学富五车 / ≥50 继续加油 / <50 初出茅庐）
  + 再来一轮按钮。

### 入口
首页快捷入口区把重复的「随机一首」替换为「飞花令」
（铜色 `Icons.local_florist` 图标），随机一首在学习进度卡片下方已独立存在。

### 测试（test/flying_flower_test.dart，12 个，全绿）
- getPoemsContainingChar：含「月」命中 2 首、找不到返回空、朝代过滤、
  随机序一致性、单字匹配、「日」匹配、「花」匹配、「明」匹配 2 首、
  title 也参与匹配（「瀑」命中标题）。
- getRandomPlayChar：返回字确实在 ≥2 首诗中出现、空库返回 null、
  不返回非汉字（10 轮验证，范围 0x4E00-0x9FFF）。

### 注意：测试 seed 数据踩坑
写测试时多次假设 seed 内容（如「望庐山瀑布」含「山」，
实际 content 是「日照香炉生紫烟」不含「山」；
「水调歌头」缩写版不含「花」）。
教训：**seed 内容必须逐字核对，不能凭记忆假设**。

## 修复诗词繁体字问题

### 用户反馈
诗词详情页、首页、搜索结果等多处显示繁体字，如"蹱"、"兩"、"漁"、"俠"、"雲"、"轉"、"遼"、"與"、"練"、"驅"等。

### 根因分析
1. `poems.json` 和离线包数据（`pack_*.json`）源自带繁体中文
2. `Poem.fromMap()` 等模型构造函数不做繁简转换，直接存储原始文本
3. 页面层的 `_t()` 函数在默认简体模式下直接返回原文（不转换）

### 修复方案（三层防线）

**数据层（根本解决）**
- 用 Python opencc 库将 `poems.json`、`poems_v2.json`、`pack_tangshi.json`、`pack_songci.json`、`pack_xiaoxue.json` 全量繁→简
- `Poem.fromMap()`、`Author.fromMap()`、`Dynasty.fromMap()`、`Category.fromMap()`、`StudyPlan.fromMap()` 现在对 text 字段统一调 `S2TConverter.toSimplified()`
- `S2TConverter` 新增 `loadFullT2S()` 方法，加载 `assets/data/t2s_mapping.json`（3751 对映射），启动时由 `main()` 调用预加载

**数据库迁移（兜底旧数据）**
- `_dbVersion` 升至 6，新增 `_convertTraditionalToSimplified()` 迁移
- 遍历 `poems` 和 `authors` 表，用完整映射表逐字转换 title/content/bio

**显示层（最终保险）**
- 所有页面的 `_t()` 函数改为：简体模式下 `S2TConverter.toSimplified(text)` 而非直接返回原文

### 影响范围
- 诗词详情页、首页、搜索、收藏、历史、诗人页、飞花令等所有显示中文的页面
- 修复后：新安装用户直接显示简体；老用户首次升级后 DB 迁移转换 + 显示层兜底

### 验证
- `flutter analyze`：0 error/warning ✅
- `flutter test`：**193 全绿**（无回归）✅
- `flutter build apk --debug`：构建成功 ✅
