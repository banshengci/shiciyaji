## 繁简转换体系完善（续 09-04 的繁体字修复）

### 发现并修复的四个缺陷

**1. 「繁体显示」设置只覆盖 4 个页面（功能不一致）**
- 现象：`poem_detail / authors / author_detail / flying_flower` 内置了 `_t()` 开关，
  而 home / search / favorites / reading_history / library / my_notes / poem_card /
  recall_quiz / settings 共 9 个页面显示诗词正文却不跟随设置。
- 修复思路：不在 9 个页面各加一遍开关，改为**模型层统一输出**。
  `S2TConverter` 新增全局 `preferTraditional` + `apply()`，
  `Poem/Author/Dynasty/Category.fromMap()` 改用 `apply()`，所有页面自动生效。
- 设置页切换时同步 `S2TConverter.preferTraditional`；`main()` 启动时 `syncPreference()`。

**2. 启动顺序 bug（严重，会导致繁体字永久残留）**
- `main()` 里 `S2TConverter.loadFullT2S()` 没 await，且排在 `DatabaseHelper.preInit()` 之后。
- DB 迁移 v5→v6 只跑一次，若此时完整映射未加载（回退到内置 270 对），
  未覆盖的字会**永久残留繁体**。
- 修复：`await S2TConverter.loadMappings()` 移到 `preInit()` **之前**。

**3. 离线包导入用了残缺转换器**
- `database_helper.dart` 导入离线包时用 `ChineseConverter.toSimplified`（仅 232 对），
  比内置的 270 对还少，会漏字。
- 修复：改用 `S2TConverter.toSimplified`（完整 3751 对）。
  `ChineseConverter` 标记 `@Deprecated` 并委托给 S2TConverter。

**4. `toTraditional` 只有 270 对，繁体显示覆盖不全**
- 测试暴露：`toTraditional('铜')` 返回 '铜'（不变），'台' 也不变。
- 修复：用 opencc 生成 `assets/data/s2t_mapping.json`（2743 对），
  `toTraditional` 优先用完整映射。
- 注意：opencc 把「钟」映射到「鍾」而非内置的「鐘」，两字都是「钟」的繁体，
  以 opencc 为准，测试期望值已同步修正。

### 上一轮遗留的两个副作用（已修）

## ③ 成就解锁实时反馈（全局横幅）（14:xx 起）

### 动机
成就体系此前「模型+判定+统计」已齐，但缺**解锁状态持久化、行为触发、实时反馈**——
用户背诗/收藏/记笔记后，成就墙 silently 更新，没有正反馈闭环，与「激励学习」的产品目标脱节。

### 实现
- 新增 `lib/core/achievement_service.dart`（`AchievementService` 单例）：
  - `SharedPreferences`（key `shici_unlocked_achievements`，逗号分隔 id）持久化已解锁集合，去重防重复弹；
  - `init()`（Splash `_init` 里 DB 就绪后调用）：加载已解锁 + `_evaluate(announce:false)` 建基线，
    **已满足的成就直接标记、不弹横幅**（避免「一进 App 弹一堆历史成就」）；
  - `sync()`：行为后调用，`_evaluate(announce:true)` 重新评估，把新解锁成就经 `onUnlock` 广播；
  - `_evaluate` 并发查 6 个 DB 统计（studied/notes/notedPoems/streak/favorite/total），
    复用 `Achievement.isUnlocked(stats)`，**不重复定义阈值**；
  - `_stream = StreamController.broadcast(sync: true)` —— **关键**：默认 broadcast 是异步派发，
    `_stream.add` 在 microtask 后才触达监听器，会导致「sync() 返回后横幅还没弹」；
    `sync:true` 让解锁**同步即刻派发**，时序确定。
  - `resetForTesting()`：仅供测试重置单例状态。
- `lib/main.dart`：`MainShell` 订阅 `onUnlock`，用 `OverlayEntry` + 队列（`_bannerQueue`）
  在顶部安全区展示 `_AchievementBanner`（新中式：朱砂印章图标 + 黛蓝标题 + 成就描述 + 淡入淡出 2.7s）；
  多成就同时解锁时顺序展示，不重叠；`dispose` 取消订阅。
- 触发点：`splash_page._init`（init 基线）、`poem_detail_page`（收藏/笔记）、`review_page`（打卡 markPoemStudied）调用 `sync()`。

### 验证
- `flutter analyze`：No issues found ✅
- 新增 `test/achievement_service_test.dart`（4 测试：基线不弹 / sync 广播并持久化 / 多成就逐个发射 / init 幂等），
  全量 **211 全绿**（207 + 4）✅
- APK 构建中（后台 x0K42K）

### 测试踩坑（重要）
1. **广播流订阅必须持有 `StreamSubscription` 引用**：`stream.listen(...)` 的返回值不保存会被 GC 回收并取消，
   导致监听器收不到事件。→ 存到变量/字段并在 tearDown 取消。
2. **广播 `StreamController.broadcast()` 默认 `sync:false`（异步派发）**：`_stream.add` 在当前同步代码之后、
   microtask 上才触达监听器；`await sync()` 返回后断言读不到。→ 业务侧用 `sync:true` 同步派发最稳妥
   （也契合「解锁即弹横幅」的体验）；若保留异步，测试需 `await Future.delayed(Duration.zero)` 等 microtask 排空。
3. **测试 DB schema 必须匹配真实表**：`study_records.study_date`（非 studied_at）、`study_notes` 表
   （非 notes，含 poem_id/content/created_at/updated_at）、`favorites.poem_id`。一开始按臆想 schema 写种子导致 SQL 报错。
4. 测试监听器用**局部变量 + 持有订阅**最稳；模块级 list 被闭包捕获时出现过「监听器追加了、断言却读到空」的隔离怪象。
