# 2026-09-06 工作记录

## Release 正式签名构建（从 debug 转向可长期自用的正式版）

### 背景
此前一直交付 `flutter build apk --debug`（≈217 MB，带调试符号、体积大、启动慢）。
用户自用场景更适合 release 版，但 release 默认无签名配置（原 build.gradle 里
`release { signingConfig = signingConfigs.debug }`），需自建签名体系。

### 实施
1. **生成私钥**（用 Android Studio 自带 JDK，避免额外装 Java）：
   `C:/Program Files/Android/Android Studio/jbr/bin/keytool.exe`
   `-genkeypair -keystore android/app/shici-release.jks -keyalg RSA -keysize 2048
   -validity 10950 -alias shici`
   （30 年有效期，自用足够；别名 shici）
2. **`android/key.properties`** 存密码与路径（storeFile 用 `app/xxx.jks`，
   在 build.gradle 里以 `rootProject.file(...)` 解析，相对 android/ 目录）。
3. **`android/app/build.gradle`**：`signingConfigs.release` 从 properties 读取；
   `buildTypes.release` 用三元判断——有配置就正式签名，无则回退 debug key，
   保证任何环境都能构建成功。
4. **暂不启用混淆/资源压缩**：Flutter + JNI/反射场景下 minifyEnabled 有崩溃风险，
   自用离线 App 收益小，注释里写明理由。
5. **私钥不入库**：`android/.gitignore` 原生已含 `key.properties`、`**/*.jks`，
   又在根 .gitignore 加了双保险（`android/key.properties`、`android/app/*.jks`、`*.keystore`），
   并用 `git check-ignore -v` 验证生效。

### 教训/要点
- 改数据或配置前先确认 App/构建真实读取路径（昨日已踩过一次 packs vs pack_* 的坑），
  这次同样先读 build.gradle 再动手。
- release 版不含调试符号，体积与启动速度都优于 debug；若还需更小，可用
  `--split-per-abi` 或 `--target-platform android-arm64` 只打 arm64。
